## A. Register amendments (Main applies; authors align prose)

A1 Hash rule (D5): frame line = `<64-hex sha256><space><canonical JSON body>\n`; digest = SHA-256 of the canonical JSON body bytes only (body contains `prevHash` and `position`); prefix, space, LF excluded.
A2 Runtime config (D5): `data/config/uta-runtime.json` is Alice-written (config routes), UTA-read with hot reload; `configRevision` is never persisted. Two-level derivation: `runtimeConfigDigest` = sha256(canonical semantic object excluding `updatedAt`); per-account `ConfigRevision` = sha256(canonical `{runtimeConfigDigest, accountConfigDigest, projectionVersion}`), `accountConfigDigest` = sha256(canonical non-secret account row). D4's "configRevision" means this per-account value.
A3 D4 persisted shapes: `attempt.started.key: KeyEnvelope`; `receipt.recorded.receipt: ReceiptEnvelope` (provenance only meaningful on `accepted`; `rejected|unknown` carry no provenance); `observation.recorded.observation: ObservationEnvelope`; `recovery.resolved.result.found` carries `{receiptEntryId, observationEntryId}` referring to `receipt.recorded{provenance: recovered}` + `observation.recorded` appended in the SAME frame; folds read only those two kinds. In-memory generic forms (`ProviderKey<P>`, `Receipt<P>`, `Observation<P>`) are obtained through `ProjectionRegistry` re-association, never `as`.
A4 D4 restart rule: on startup, for every `attempt.started` without a receipt, the Reconciliation consumer appends `receipt.recorded{unknown{cause:'processRestart'}}` BEFORE running the witness. Unknown causes = `timeout | disconnect | noResponse | processRestart | parseFailure` (`parseFailure` = response received but undecodable after send evidence).
A5 D4 statuses: no `recorded` status; a `withdraw` after `attempt.started` is an audit entry, execution outcome unchanged. Manual recovery = `recovery.resolved{result: manual{resolution: abandon | continue | awaitingReview, principal}}`; it is a review-flow action distinct from `DecisionAction`. `confirmedAbsent` is the canonical name for the constraint's `MissingRemote` (say so once in 04).
A6 Tokens: `awaitingReview`, `review.unknownOutcome` etc. are the protocol/ledger literals; hyphenated forms are UI copy only. Legacy path is `GET /api/trading/uta/:id/quote/:symbol`. Mapping = 39 trading + 9 simulator + `/__uta/health` = 49 rows.
A7 D12 drain: while draining, effective attempt deadline = min(provider-declared deadline, `drainBudget = launcherGrace − 1000 ms`); unresolved at cap → process exits, durable `attempt.started` classified per A4 on restart. On the atomic `draining` transition: reject non-durable queued commands with `ServiceDraining`; durable intents/decisions remain for restart; `AppendStore.close()` waits only for the (now deterministic) empty queue.
A8 D2: `effect` is a runtime dependency of `services/uta` only; the private types package has it as a dev-only fixture dependency. Generated OpenAPI clients are Effect-free and are invoked only through the transport adapter's Promise wrapper; no generated-client value enters core serialization. Control values (`AbortSignal`/cancellation context, deadlines) are exempt from the "serializable business values" rule at the Pack ABI; they never persist.
A9 D3: `PackModule<D extends ProviderDeclaration>` — handlers (`recovery`, transport bindings) are keyed by the write kinds whose status is `supported` in `D` (mapped type), so a Pack's own typecheck fails when a supported kind lacks its witness; the loader mirrors this at runtime and returns `LoaderValidationResult` (`loaded{module} | invalid{code: ApiVersion|DeclarationInvalid|MissingHandler|NonSerializable|ProjectionIdentity, path}`). `ProviderEnvelope` carries `kind: OperationKind`; envelopes are role-indexed (`OperationEnvelope`, `KeyEnvelope`, `ReceiptEnvelope`, `ObservationEnvelope`, `ConfigEnvelope`) so roles cannot be swapped; `P`'s phantom is `(ProviderId, ProjectionVersion)`. A `supported` write row without a constructible witness is a load-time `MissingHandler`.
A10 D7/D9: `intentId`, `proposalId`, `decisionId` are caller-generated stable identities; UTA validates and records, never allocates. Alice bridge `DecisionRequest{decisionId, action, scopeHash}` → Alice resolves scope → UTA `AuthorizationDecisionRequest{decisionId, action, scope, scopeHash}`. `selfApprove` may not contain `system`. `WorkRequested`: `freshness.asOf` nested (no top-level asOf); `admissibleDecisions` non-empty for `review.*`, `reconcile.*`, `intent.awaitingAuthorization`, may be empty for `watch.triggered`/`news.received`; `review.ruleRejection` additionally carries `{consumer, ruleId, configRevision, reasonTree}`; `Origin` gains `watch{sourceEntryId, sourcePosition, cursor?, eventId?}` and `news{sourceEntryId, sourcePosition, cursor?, eventId?}` variants.
A11 D8/wire: `/v2/events` `wait` ≤ 25000 ms; bridge sends `min(pollIntervalMs, 25000)`; reaching the wait deadline returns 200 with empty `items` and unchanged `nextCursors`; `Timeout` only for server overrun. `EventItem.entry` is a `LedgerEntryWire | UnknownLedgerEntryWire` (never `ProviderEnvelope`); correlation is inside the entry. Statuses: `POST /v2/accounts/:id/intents` new=201 / duplicate=200; `POST /v2/intents/:id/decisions` new=202 / same decisionId=200; `ProviderUnknown`=503; `ServiceDraining`=503; `InternalError` (new code)=500 with safe message; `DurabilityFailure` → 503 `ReadinessUnavailable` with structured diagnostics in readiness; `CapabilityUnsupported`=422 only. Simulator state actions return `CommandResponse{kind:'completed', requestId}` (no ledger position). Bearer-only (no business Principal) for `/__uta/health`, `/v2/readiness`, `/v2/openapi.json`; everything else bearer + Principal. Readiness is a local snapshot: 200 or 503, no 504. `x-uta-channel` ∈ {`read-only`,`read-write`} only; lifecycle/simulator classification lives in `x-uta-kind`. Config-invalid errors are `ConfigError{path, code, message}[]`, never `string[]`. `writable` reasons are the finite tagged set (add `QuarantineCapacityExceeded`, `Draining`, `FirstObservationRequired`); `ReadinessUnavailable` is an HTTP-level code only.
