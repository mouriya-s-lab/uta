# UTA public surface and Alice consumers

## Decision questions answered

1. The UTA service exposes 49 mounted HTTP endpoints: 39 trading routes, 9 simulator routes, and `GET /__uta/health`. The table below maps each to the new IO class, callers, repeated-request semantics, side effects, mode gates, and wire/error source. `[observed]` facts are source-grounded; `[inferred]` conclusions are explicitly marked.
2. One route has no repository caller: `GET /api/trading/uta/:id/quote/:symbol` (legacy path). All other 48 have a live UI, SDK/tool, bars, connector, supervisor, config, or simulator caller; some are indirect through the generic BFF or CLI tool registry.
3. UI hand-copies broker/account/health, positions, history, wallet/git, config, and snapshot shapes. `ui/package.json` has no `@traderalice/uta-protocol` dependency. The protocol barrel exports types, client, broker-preset/search helpers, and two research schemas; `schemas/index.ts` is only `export {}` despite its comments.
4. The reported Alice→UTA reverse-import set needs a count correction on this checkout: there are 21 executable references (20 static imports plus one dynamic config import) and one compatibility comment. The earlier 21-total report omitted `services/uta/src/domain/trading/fx-service.ts:13`; the actionable executable set is therefore 21, while the comment is not a dependency. These references bind UTA startup, config, paths, event log, tool registration, broker packs, FX market-data clients, snapshot pump/store, and test-connection parsing to Alice source. A further 12 test-only imports exist and are listed as a contradiction below.
5. A one-release compatibility facade must preserve effective paths/methods, request coercions/defaults, response/error shapes/statuses, resource/CAS identities, mode/trust gates, hidden recovery and persistence side effects, decimal-string precision, and process/config semantics. Atomic migration may change paths and wire envelopes only after every listed consumer (including CLI, connector, bars, UI, demos, and config/BFF) is migrated together; user-visible approval/CAS, source/tier filtering, history, provenance, and mode behavior still remain semantic requirements.

## Observed facts — cross-cutting boundary

- `[observed]` UTA mounts `/api/trading` and `/api/simulator`, binds only to `127.0.0.1`, and exposes health at `/__uta/health` (`services/uta/src/main.ts:145-176`). The UTA route layer has no request-auth principal; Alice's web auth and the loopback host are the trust boundary (`src/webui/routes/trading-proxy.ts:1-12`, `src/webui/plugin.ts:254-266`).
- `[observed]` The BFF forwards the effective path, query, body, selected headers, and upstream status/body; it has a 30s timeout (`src/webui/routes/trading-proxy.ts:115-187`). It returns lite `503` before forwarding and readonly `403` only for `wallet/push`, one-shot venue writes, `simulate-price`, and all simulator paths (`src/webui/routes/trading-proxy.ts:115-136,193-205`). Stage/commit/reject and reconnect are not readonly venue mutations.
- `[observed]` The SDK uses a 15s abort timeout, does not retry, does not validate response schemas, parses non-JSON bodies as strings, and turns non-2xx responses into `UTAHttpError(status, body, message)` (`packages/uta-protocol/src/client/UTAClient.ts:48-102`). UI fetch helpers similarly do no retry; tool fan-out uses `Promise.allSettled` to retain healthy accounts (`src/tool/trading.ts:68-82`).
- `[observed]` `queryAccount` maps offline to `503 {error,health}` and calls `nudgeRecovery()`, maps permanent `BrokerError` to `500`, and transient errors to `503 {error,code,transient}` (`services/uta/src/http/routes-trading.ts:98-125`). Routes outside `queryAccount` use local `404`/`400`/`500` mappings instead.
- `[observed]` No route accepts a general idempotency key. `expectedPendingHash` on push/reject is an optimistic-concurrency/CAS token, not an idempotency key (`services/uta/src/http/routes-trading.ts:85-89,474-527`). The BFF forwards `x-request-id`, but the UTA route code does not consume it (`src/webui/routes/trading-proxy.ts:29-34,144-148`).
- `[observed]` Persistence ownership is split: Alice validates/seals/writes `accounts.json` (`src/core/config.ts:704-788`); UTA reads it at boot and owns trading/snapshot state (`services/uta/src/main.ts:56-83`, `services/uta/src/main.ts:102-127`). Snapshot GET routes only call `getRecent`; no snapshot endpoint calls `sync`; scheduled/post-push snapshots are separate scheduler/hooks (`services/uta/src/http/routes-trading.ts:639-725`, `services/uta/src/main.ts:102-111`).

## Recommendations — compatibility-facade decision (Q5)

### If old HTTP paths remain for one release

`[inferred]` The facade's minimal semantic contract is:

1. Preserve all 49 effective method/path pairs, including the otherwise-dead legacy `GET /uta/:id/quote/:symbol`, mount prefixes, query aliases (`pattern|query`, `source|accountId`), and path/body selectors (`aliceId`, `subAccountId`, `hash`, `timestamp`, `orderId`, `nativeKey`).
2. Preserve wire coercions/defaults: Decimal-sensitive trading numbers remain strings; simulator accepts string-or-number numerics; sync/simulate malformed JSON falls back to empty input; wallet log/history/snapshot/equity-curve limits retain defaults; snapshot/equity-curve `startTime/endTime` remain either implemented consistently or deliberately ignored with the old observable result.
3. Preserve response envelopes and conditional fields: `{utas}`, `{results,count,utasConfigured?}`, `{rates}`, `{positions}`, `{orders}`, `{commits}`, `{trades}`, `null` contract details, raw broker research pages, git status/commit/push/reject shapes, `{snapshots}`, `{points}`, and simulator `{filled}`/`{ok:true}`. Preserve UI's `Wallet*` interpretation until UI migrates.
4. Preserve status/error mapping, not just error text: `queryAccount` offline 503 with health, BrokerError permanent 500/transient 503, route-local 400/404/500, wallet 409 `PENDING_HASH_REQUIRED|PENDING_HASH_CONFLICT`, one-shot `{error,phase}` status split, simulator 400/404, and the current `test-connection` success/error body.
5. Preserve identity/concurrency semantics: no invented idempotency; `expectedPendingHash` remains an optimistic CAS token; push/reject remain non-idempotent; stage→commit→push ordering and pending-hash persistence remain visible; reconnect remains a process-lifecycle operation with its current result shape.
6. Preserve hidden/final side effects: equity's recovery nudge and FX reads; test-connection's create/init/read/close without registration; sync/git append; push's broker submission; snapshot read/error-collapse behavior; simulator in-memory mutations; config writes' secret masking, sealed `accounts.json`, and Guardian restart.
7. Preserve trust and transport boundaries for the release: Alice auth/loopback principal, BFF lite/readonly gates, 30s BFF and 15s SDK timeouts/no retries, selected header forwarding, and health's exact `ok/startedAt/utas` readiness shape.

### If consumers migrate atomically

`[inferred]` The facade need not preserve old path names or accidental response envelopes, but the migration is complete only when all of these semantic obligations are updated together: SDK manager/account adapters; all 26 tools; `alice-uta` command catalog and strict flag schemas; connector review/push/reject; Bars gateway historical/details/search/capability logic; UI API/pages/hooks/live polling and hand-copied types; BFF/config/test-connection; supervisor/Guardian health/restart; demo handlers/spec fixtures; and provenance extraction of commit hashes. The dead legacy quote path may then be removed, and route-local errors may be replaced by structured errors, only if every in-repo caller has moved and any external-client assumption is explicitly rejected. `[inferred]` Atomic migration does not permit changing approval CAS, decimal precision, source/tier filtering, account/wallet scoping, history/provenance identity, or lite/readonly/pro gates as incidental cleanup.
