# 会话入口

## 0 定位

- **层级与元素**：L3 component。核心进程内的“会话入口”组件：核心↔解释层会话（消费方会话）的开始与结束。
- **上级文档**：[core-process/design.md §4.1 组件指南](design.md#41-组件指南)（核心进程 L2）。
- **本文决定什么**：消费方会话怎样建立、principal 怎样组成、会话不拥有什么、启动期与停止期怎样对待请求、未完成握手的请求怎样拒绝；核心↔解释层契约的会话部分与几项已定事实（独立生命周期、重连语义、没有“同步”操作）。
- **读者**：核心实现者；解释层作者。
- **状态**：已定。
- **非目标**：
  - 各操作组的规格：订阅组在 [subscription.md §4.1 核心↔解释层：订阅组与 rewind_cursor](subscription.md#41-核心解释层订阅组与-rewind_cursor)，一次性读在 [one-shot-read.md](one-shot-read.md)，读模型与健康在 [read-model.md §4.2 读模型集合](read-model.md#42-读模型集合)，单据组在 [ticket.md §4.3 单据组（核心↔解释层）](ticket.md#43-单据组核心解释层)，结果未知组在 [io-shell.md §4.8 结果未知组（核心↔解释层）：放弃跟踪与重开](io-shell.md#48-结果未知组核心解释层放弃跟踪与重开)，控制组在 [control-plane.md §4.1 控制组的操作集与各自的规格所在](control-plane.md#41-控制组的操作集与各自的规格所在)。
  - 写授权与控制授权的规则本身：[decision-chain.md §4.2 顺序固定链：授权 → 输入约束 → 审批 → lane → 过期](decision-chain.md#42-顺序固定链授权--输入约束--审批--lane--过期)。
  - 解释层对下游的对外面（命令、长连接消息、续传令牌）：[downstream/design.md §4 结构](../../downstream/design.md#4-结构)。

## 1 问题域

### 1.1 上级分配的需求

| 编号 | 本组件承担的部分 |
|---|---|
| P13 | 消费方会话：对端、principal |
| H7、C11 | 信任单位是 OS 用户；每个会话绑定一个经传输无关机制认证的 principal |
| H5、C5 | 订阅与程序的生命周期由核心拥有，与消费方连接无关 |
| Q19 | 伪造请求体身份、未认证连接被拒，安全事件可读 |
| Q29 | 下游断连重连后按已确认 cursor 续收，损失显式 |

### 1.2 本组件直接面对的域

- **消费方**：解释层代下游（Alice、CLI 使用者、外部客户程序）开的会话。下游是独立生命周期的消费方与控制方，只经解释层接触核心；本契约的消费者只有解释层，所以本契约可以用核心的抽象写（[README.md §4.1 划分与理由](../../README.md#41-划分与理由)）。解释层为每个下游连接（一次性命令或一条长连接）开一个核心会话，以该下游自报的 actor 握手。下文“消费方”“会话”都指这种会话。
- **OS 传输**：UDS 给出对端凭据（peer credential），命名管道给出 ACL，二者的粒度都是 OS 用户（H7）；Windows 缺少 UDS，退化为本地回环 + 本地令牌或命名管道。本机非本用户的进程不可信；本用户的进程视为用户本人：它们本就能读该用户的文件与进程环境。
- **核心实例**：会话只在一个实例的内存里；实例重启后会话全部不在，下游重连面对的是新实例。

## 2 驱动

| 场景 | 本组件的响应度量 |
|---|---|
| Q19 | 未完成握手的写或控制请求：不进入任何处理器、无单据、无 venue 调用、无配置变更，安全事件可读（验收 [control-plane.md §6.2 验收标准](control-plane.md#62-验收标准) #13） |
| Q29 | 下游或解释层崩溃、重启：核心的订阅、程序、lane 与日志不变；重连后投递从已确认 cursor 续（主 trace [core-process/design.md §5.1 W14（Q29）下游（Alice）断连重连](design.md#w14q29下游alice断连重连)） |

## 3 模型

- **消费方会话**：以 `handshake` 建立，是核心实例的内层，只在内存里。它**不拥有任何持久对象**：订阅归属 principal、止于 `unsubscribe`；单据归属其负责人；它发起的一次性读由一次性读组件完成。所以会话结束不结束这些对象，也不写记录 [设计]。
- **principal = `(os_user, actor)`**：`os_user` 来自传输给出的 OS 对端凭据，是 H7 信任边界；`actor` 是下游自报的会话内身份（哪个 AI / 哪个人），由解释层带入握手。同用户进程视为用户本人，所以 `actor` 无需第二重认证：它是审计与 scope 的键，不是信任来源。
- **同机能连上 ≠ 有权发写**：写权限来自认证得到的 principal × 策略 scope，不来自连接。
- **不变量**：
  1. 除 `handshake` 外，未完成握手的连接上的请求不进入任何处理器。
  2. 每个请求的身份只取会话绑定的 principal，请求体里的身份字段不参与授权。
  3. 会话的开始与结束不产生、不改变任何持久对象。
  4. 启动第 5 步开放下游会话之前，除 `handshake` 外的操作一律返回 `Starting`。
- 理由（信任单位是 OS 用户）：核心是独立进程后，IPC 成为正式边界，而 UDS 对端凭据与命名管道 ACL 的粒度都是 OS 用户。代价：同用户进程之间不互相隔离；要求进程间隔离需能力令牌 / 管道句柄传递，是一条升级路径（会推翻它的观测：[README.md §6.1 证伪条件（部分级）](../../README.md#61-证伪条件部分级) #8）。

## 4 结构与接口

**拥有**：消费方会话的开始与结束、principal 的组成、契约版本检查、启动期的 `Starting`、受控停止时关闭入口与全部会话、未完成握手请求的安全事件。
**隐藏**：传输（UDS / 命名管道 / 回环 + 令牌）。
**假设**：信任单位是 OS 用户；消费方会话不拥有订阅、单据或在途读。

### 4.1 `handshake(contract_version, actor) → Session{principal, instance_id, contract_version}`

- **语义**：在一条已由传输给出 OS 对端凭据的连接上建立会话。`principal = (os_user, actor)`。`Session.instance_id` 是本核心实例的序号，让解释层看出重连后面对的是不是同一个核心实例（一次性读的 `Pending` 据此判断等待保证是否仍有效，[one-shot-read.md §4.2 核心↔解释层：read](one-shot-read.md#42-核心解释层readtargets-deadline--vectargetresult)）。
- **动作轴**：非动作。
- **核心内部结果**：无记录。
- **错误**：
  - 对端不是本 OS 用户 → 传输层拒绝连接（下游连到解释层的对外端点时，解释层同样取 OS 对端凭据，非本用户拒绝）；
  - 契约版本不兼容 → 拒绝会话，把原因返回给解释层；不 append 记录；
  - 受控停止第 1 步之后 → 入口已关闭，不接受会话。
- **启动期**：启动第 5 步开放下游会话之前（[core-process/design.md §4.7.3 启动五步](design.md#473-启动五步)），会话可建立，但除 `handshake` 外的操作（含 `health`）一律返回 `Starting`，不给部分状态：第 2 步重建完成之前连健康的 fold 都还没有，之后到第 5 步之间给出的也只是半恢复的状态。开放之后个别集成 `Connecting` 或 `Halted`、个别程序不可用都不使任何操作返回 `Starting`：各自的会话与程序状态照实可见。

### 4.2 请求的身份与授权的入口

- **未完成握手**：连接在 `handshake` 返回 `Session` 之前发起的任何写或控制请求，本组件拒绝，不进入任何处理器，并 append 一条安全事件（执行事实，P7）。本组件的执行事实只有这一种（[core-process/design.md §4.3.4 执行事实的唯一写入口](design.md#434-执行事实的唯一写入口)）。
- **已完成握手**：每个请求带上会话绑定的 principal 交给对应组件；请求体里的身份字段不参与授权。
- **授权分三类**，都由接收请求的组件按同一规则族判定，本组件只提供 principal：
  - 写类操作（单据组）按 `(principal, WriteLaneKey, OperationKind)`，在 STS 授权步（[decision-chain.md §4.2 顺序固定链：授权 → 输入约束 → 审批 → lane → 过期](decision-chain.md#42-顺序固定链授权--输入约束--审批--lane--过期)）；
  - 控制动作与结果未知组按 `(principal, 动作种类)`（[control-plane.md §4.2 共同流程](control-plane.md#42-共同流程)）；
  - **读不另授权**：一次性读、订阅与读模型不按 principal 授权。信任单位是 OS 用户，同用户进程视为用户本人；principal 在读上只是订阅的归属与读记录出处里的发起方。

### 4.3 订阅归属与重新挂接

消费方的订阅归属 principal。同一 principal 的新会话自动重新挂接它的持久订阅，投递从已确认 cursor 续，不需要重新 `subscribe`（挂接与投递的规则在 [subscription.md §3.2 cursor 与确认](subscription.md#32-cursor-与确认)、[delivery.md §5.2 W14 的投递细化（重新挂接）](delivery.md#52-w14-的投递细化重新挂接)）。程序订阅不经消费方会话挂接、确认或改动。

### 4.4 会话的生命周期 [设计]

| 对象 | 开始锚点（确认者） | 结束锚点（确认者） | 外层 | 持久痕迹 |
|---|---|---|---|---|
| 消费方会话 | `handshake` 返回 `Session`（OS 对端凭据 + 本组件） | 传输关闭：对端关闭，或受控停止第 1 步由本组件关闭；实例死亡（核心） | 核心实例 | 无 |

- 受控停止第 1 步：本组件不再接受消费方会话，并关闭已有的全部会话（[core-process/design.md §4.7.4 受控停止](design.md#474-受控停止-设计)）。停止之前已在执行的控制动作照常完成，结论写在记录里；发起方重连之后从记录得知结果（[control-plane.md §4.5 受控停止期间](control-plane.md#45-受控停止期间)）。
- 理由：会话若拥有订阅或单据，下游断连就会带走核心的状态，违反 C5；在途读若随会话结束，`Pending` 之后就没有人提交结论与计数。
- 不选：**订阅随连接存亡**：重连要重订，断连期间的需求丢失（会推翻它的观测：[README.md §6.1 证伪条件（部分级）](../../README.md#61-证伪条件部分级) #7）。

### 4.5 传输与 IDL

- 核心↔解释层的语义由一份 IDL 固定，同一 JSON-RPC；传输按 OS 选择（UDS / 命名管道 / 回环 + 本地令牌），只改编码与信道，不改 IDL。编码取舍见 [core-process/design.md §4.7.1 进程形状](design.md#471-进程形状)。
- 本契约消息 schema 的文本形式随 IDL 文件留在本仓库内部，不对下游发布；对下游发布的是解释层的对外面（[downstream/design.md §4.6 身份与发布物](../../downstream/design.md#46-身份与发布物)）。

### 4.6 已定事实

- **独立生命周期**：下游或解释层退出、崩溃、重启不改变核心的订阅、程序、lane、日志（H5 / C5）。
- **重连语义**：解释层代下游重连后握手，按 `as_of` 读读模型取当前状态，从已确认 cursor 之后订阅记录（观察流与执行事实同一套）。断连期间的投递损失是订阅上的 `Gap{origin: Delivery}`，重新挂接时先于记录交出，不伪造连续性；解释层把它翻成下游的缺失通知。执行事实订阅没有投递损失。
- **没有“同步”操作**：核心不提供把自己持有的状态对齐到上游的操作，因为它不持有上游原值（[README.md §1.1 根本约束：权威不在 UTA](../../README.md#11-根本约束权威不在-uta)）。旧入口 A08 `sync`（及 A37 账户快照捕获前的 best-effort `sync`）在新边界上是一次性 `read`：产生新的观察记录，以观察为输入的读模型随之 fold；返回的是该次读的结论与记录位置，不是“更新了几条”。账户快照本身不由 UTA 提供（[README.md §0.3 非目标](../../README.md#03-非目标)）。

## 5 组件内走查

### 5.1 W19 第 1、2 步的本组件细化（Q19）

1. 未认证连接发起 `draft` 或 `restart_integration`：本组件发现该连接没有 `Session` → 拒绝，append 安全事件；请求没有到达单据或控制面。对外可见：无单据、无 venue 调用、无配置变更。
2. 已认证会话（principal P）在请求体里填另一 principal Q 发 `draft`：本组件把 P 交给单据；单据以 P 为 `responsible` 开单，STS 授权步按 P 判定，越权时授权步 append 安全事件（[decision-chain.md §4.2 顺序固定链：授权 → 输入约束 → 审批 → lane → 过期](decision-chain.md#42-顺序固定链授权--输入约束--审批--lane--过期)）。Q 没有参与任何判定。
- 主 trace 与验收：[core-process/design.md §5.1 W19（Q19）会话身份与未授权控制](design.md#w19q19会话身份与未授权控制)，验收 #13。

### 5.2 W14 的本组件细化（Q29）

主 trace：[core-process/design.md §5.1 W14](design.md#w14q29下游alice断连重连)。

1. 下游 Alice 崩溃：解释层关闭它的连接 → 本组件结束这个会话，不写记录；订阅、单据、在途读都不受影响。
2. Alice 重启，解释层以同一 actor 重新 `handshake` → 新 `Session`，`principal` 与之前相同；`instance_id` 不变即同一核心实例。
3. 持久订阅按 principal 自动挂接：未确认的投递缺口先于记录交出，再交 cursor 之后的记录。
- 核心在其间重启：新 `Session.instance_id` 不同，解释层据此知道此前 `Pending` 的等待保证已失效。

### 5.3 启动期与停止期

- 启动第 3 步时有消费方连上：`handshake` 成功，`read_model` 得 `Starting`；第 5 步之后同一会话的请求照常处理。
- 受控停止第 1 步：入口关闭、全部会话关闭；停止中不写会话记录。

### 5.4 卡点

逐步走过 4.1–4.6 与上面三条，没有登记卡点：每个请求的身份来源、每种拒绝的记录与写者都已定义。契约版本不兼容只拒绝会话、不写记录（4.1），因为会话不拥有持久对象，这次拒绝也不是越权或控制动作。

## 6 评估

- **风险 / 敏感点**：信任单位 = OS 用户是本组件唯一的敏感假设；它的证伪条件（#8）与“订阅随连接存亡”的证伪条件（#7）是部分级决定，定义在 [README.md §6.1 证伪条件（部分级）](../../README.md#61-证伪条件部分级)。
- **验收**：本组件没有单独编号的验收项；它的行为由 #13（[control-plane.md §6.2 验收标准](control-plane.md#62-验收标准)）与 W14 的主 trace 覆盖。
