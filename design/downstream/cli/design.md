# 一次性命令（`uta` CLI）

- **层级与元素**：C4 L2 container：解释层的一次性命令，在 `uta` CLI 进程里运行，随命令启停。上级文档：[../design.md §4.1 容器](../design.md#41-容器)。
- **决定什么**：本容器由哪些组件构成；命令的形态与输出；写命令与读命令返回什么；哪些参数与字段手写、哪些在构建期生成，构建时与运行时 schema 版本不同怎样处理；W20 的命令各步。
- **读者**：实现 `uta` CLI 的人；CLI 使用者（人、AI）。审批者：无（K3）。
- **状态**：已定。
- **非目标**：
  - 核心↔解释层契约各操作的规格：由 core 拥有，总表见 [core-process/design.md §4.2 对外接口总表](../../core/core-process/design.md#42-对外接口总表)。本文只引用。
  - 对外说法与请求的解析：翻译组件定义在长连接端点容器（[../endpoint/translation.md](../endpoint/translation.md)），本容器使用它。
  - 命令与 flag 的具体名字：实现阶段制品。

证据标签与编号前缀的约定见 [README.md §0.4 阅读约定](../../README.md#04-阅读约定)。

## 1 分配给本容器的需求与它面对的域

### 1.1 上级分配的需求

需求编号见 [../design.md §1.3 分配给解释层的需求](../design.md#13-分配给解释层的需求)。本容器承担：

| 需求 | 本容器承担的部分 |
|---|---|
| Q2–Q4、Q9 | 写命令返回于下游能理解的稳定状态之一（§4.2），说法由翻译给出 |
| Q13、Q15、Q16 | 读命令的逐项结果经翻译给出，不返回看似成功的空结果（§4.2） |
| C11、Q19（依 H7） | 命令在本 OS 用户的进程里运行，以下游自报的 actor 开核心会话（[../design.md §4.2 身份与发布物](../design.md#42-身份与发布物)） |

### 1.2 本容器直接面对的域

- **CLI 使用者**：人或 AI，一次一条命令，读输出后决定下一条；它自己保存命令返回的请求引用与读取令牌。
- **构建期的输入**：类型与各集成的发布制品（扩展 schema 与记录映射）在构建时可得（[README.md §4.2 部分之间的关系](../../README.md#42-部分之间的关系)）。

## 2 驱动

| 场景 | 本容器的响应 | 响应度量 |
|---|---|---|
| 泄露检查 | 命令帮助与输出不出现核心概念名 | [验收 #23](../design.md#62-验收) 第 1 条 |
| 来源专有字段随构建 | 只有扩展了字段的来源下出现对应参数与字段；构建时没有的 schema 版本如实提示 | 验收 #23 第 8 条 |

## 3 模型

- **一次命令一个核心会话**：命令结束即会话结束；每次命令按当时的 `sources` 与 `health` 解析（[../endpoint/translation.md §4.1 请求的解析：此刻能不能](../endpoint/translation.md#41-请求的解析此刻能不能)）。本容器不持有状态（[../design.md §3.1 解释层不持有状态](../design.md#31-解释层不持有状态)）。
- **命令在构建期定下**：命令与参数是否存在在构建时就定了，运行期只回答“此刻能不能”（§4.3）。

## 4 结构

### 4.1 组件

| 组件 | 拥有 | 隐藏的决定 | 假设 | 文档 |
|---|---|---|---|---|
| 一次性命令 | `uta` 命令行、输出格式 | 命令与 flag 的名字、人读输出的措辞 | 一次命令一个核心会话 | §4.2 |
| 构建期生成 | 订单参数、读侧字段与查询参数、来源专有参数与字段 | 生成器实现 | 类型与集成发布制品在构建时可得 | §4.3；长连接端点容器也使用它 |

命令经翻译组件把请求落到核心的操作、把结果翻成对外说法（[../endpoint/translation.md](../endpoint/translation.md)）。

### 4.2 命令的形态

- 来源作用域的命令：`uta <来源> <名词> <动词> [参数]`，例如 `uta ibkr order list`、`uta ibkr position list`。不属于某个来源的名词（审批、策略程序、原生计算组件、连接状态、运维）不带来源一段；策略程序具名输出的目标怎样给出见 [../endpoint/translation.md §4.2 策略程序的具名输出](../endpoint/translation.md#42-策略程序的具名输出)。
- 输出默认给人读；结构化输出按解释层发布的对外 schema（[../design.md §4.2 身份与发布物](../design.md#42-身份与发布物)），不是核心记录。
- 写命令返回于下游能理解的稳定状态之一：待审、已受理、被拒、未发送、结果未知；或返回于调用方指定的等待上限，此时给出当前状态。返回的请求引用供后续命令使用。
- 读命令在等待上限内尚未作答时给出读取令牌（[../endpoint/translation.md §4.4 读取令牌](../endpoint/translation.md#44-读取令牌)）。

### 4.3 命令与参数从哪里来

**手写的**：核心概念翻成对外说法的部分。对外概念与动词（[../endpoint/translation.md §3.1 对外概念](../endpoint/translation.md#31-对外概念)）、状态与结果的翻译（[../endpoint/translation.md §4.3 状态与结果的翻译](../endpoint/translation.md#43-状态与结果的翻译)）、错误文案都逐条写出，不生成。理由：这是清洗本身，每一项都需要判断。

**生成的**：本来就是下游词汇的部分，由构建期生成组件产出。

- 订单参数：写侧基本类型的已注册字段（处理器字段注册表里的守卫字段，如 side、instrument，[envelope.md §3.2 处理器字段注册表](../../core/core-process/envelope.md#32-处理器字段注册表)），以及该来源为每种操作声明的意图参数 schema（公共意图 schema 或其扩展，含订单类型、time-in-force 等没有处理器读的参数；核心按它校验、不读其值，原样交给集成，[ticket.md §3.4 参数合规：意图参数 schema](../../core/core-process/ticket.md#34-参数合规意图参数-schema-设计)）；
- 读侧字段：公共 schema。成交的执行身份与修订号也是公共 schema 字段，对外以成交编号、修订号给出：下游自行计数时读的就是它们，与核心 `orders` 读的是同一个值（[read-model.md §3.2 成交的计数身份](../../core/core-process/read-model.md#32-成交的计数身份-设计)）；
- 读侧查询参数：各流的请求 schema（公共请求 schema 或来源扩展，[integration-session.md §3.3 投影 Projection](../../core/core-process/integration-session.md#33-投影-projection)）：查询主体（已解析的 instrument、目录键或文本）与领域过滤条件（到期日、行权价、条数上限等）；时间段落到核心的 `range`；
- 来源专有的参数与字段：该集成发布的扩展 schema 与记录映射（[README.md §4.2 部分之间的关系](../../README.md#42-部分之间的关系)）。

生成在构建期完成，从类型与集成的发布制品生成，不在运行期远程发现。命令是否存在在构建时就定了；运行期只回答“此刻能不能”（[../endpoint/translation.md §4.1 请求的解析：此刻能不能](../endpoint/translation.md#41-请求的解析此刻能不能)）。

构建时与运行时的 schema 版本不同：

- 运行期遇到构建时没有的载荷 schema 版本：该来源专有的字段不可用并如实提示，公共字段不受影响。这与核心“未注册的 schema 组合不触发解释器”一致（[envelope.md §3.3 payload_schema 与 schema 发布](../../core/core-process/envelope.md#33-payload_schema-与-schema-发布)）。
- 构建时的请求 schema 或意图参数 schema 版本与该来源此刻声明的不同：该读或该操作如实提示暂不能执行，不提交旧版参数（[one-shot-read.md §4.2 核心↔解释层：read](../../core/core-process/one-shot-read.md#42-核心解释层readtargets-deadline--vectargetresult)、[decision-chain.md §4.2 顺序固定链：授权 → 输入约束 → 审批 → lane → 过期](../../core/core-process/decision-chain.md#42-顺序固定链授权--输入约束--审批--lane--过期)）。

## 5 走查

### 5.1 W20 第 1、3 步的本容器细化

主 trace：[core-process/design.md §5.1 W20](../../core/core-process/design.md#w20q13q15q16解释层取得声明按账户与无账户来源读推送待审与结果未知)；容器级 trace：[../design.md §5.1](../design.md#51-w20q13q15q16取得声明按账户与无账户来源读推送待审与结果未知)。

- 第 1 步：构建期，生成器从公共 schema 与集成 X、公共来源 P 的发布制品生成命令参数与字段。
- 第 3 步：下游读 X 两个账户的持仓与 P 的某 instrument 报价。→ 命令按 `sources` 解析到各自的流，带请求 schema 身份与参数发一次性读；各 target 的结果逐项翻译：X 离线得“来源离线，正在重连”（先于能力判定），P 作答得数据，上游拒绝得“来源拒绝”，迟迟不答得读取令牌。
- 走通。每步只用翻译表的一行或 `sources` 的一次读；没有需要解释层保存的状态。卡点：无。
