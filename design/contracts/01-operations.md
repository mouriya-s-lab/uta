# 契约 01：操作

本文件把 `uta-design.md` §2 的规则写成契约 A（集成 ↔ 核心）和契约 B（客户端 ↔ 核心）。它只描述方向、发起者、前置、请求字段、结果 ADT、幂等键和顺序保证；没有在 §2 之外增加状态、默认值或回退。

## 0. 共同约定

### 0.1 会话、身份与权限

- 会话认证从传输边界得到身份。请求体不携带身份；核心以会话身份为准（`uta-design.md:169`、`uta-design.md:245`）。
- 契约 A 的集成会话身份是 `Integration(AccountId)`，只能写回同一账户的帐票与行情记录，并可报告自己的能力声明与递送进度。
- 契约 B 的会话身份是 `Client(名称)` 或经过授权的 `Human(名称)`。核心按账户用途、身份和策略判定读写权限；策略或配置读不到时拒绝。
- 未认证连接直接断开并记安全事件；已认证但越权的操作返回该操作列出的 typed 失败并记安全事件。传输断开不是业务结果 ADT 的隐含分支。
- 请求时限由传输的 `deadline` 表达；它不改变已递出的指令状态（`uta-design.md:208`）。本文件不为请求另外发明时限字段。

### 0.2 标识、帐票与 ADT

- `InstructionId = (AccountId, 客户端幂等键)`。同一账户同一客户端幂等键重复提交时返回同一指令，不新建第二条（`uta-design.md:167`）。
- `broker 原生 id` 与 `client key` 都是不透明值。前者来自回票；后者由核心随指令下发，只有能力声明有 broker 文档化幂等语义时才用于关联与回读（`uta-design.md:168`）。
- 递送进度包括：已交集成、调用许可、结果不明、未递；递送进度引用指令和尝试号（`uta-design.md:178`）。
- 回票种类是：状态回票（受理、部分成交、成交、被拒、撤销、专有状态）、成交回票、佣金补录、成交冲突。状态回票保留 broker 原生 id、状态原值、累计字段和原始负载摘要；成交回票保留 broker 成交 id、逐笔字段、佣金和 broker 时间；表外状态保留原值、标不明并告警，同时追加种类为 `未映射状态` 的帐票，不映射成被拒（`uta-design.md:179`、`uta-design.md:206-207`）。
- 对账响应包括持仓、订单列表、账户、回读结果；外部变动不引用指令；人工凭证由 Human 身份签发；缺口引用流、前一段最后 seq 与原因（`uta-design.md:180-183`）。
- 各节的“结果 ADT”就是该操作的穷尽 `oneof`。没有列出的传输断开不作为另一个业务结果。没有在 v2 定义的载荷或原因列入文末卡点表，不以通用结果代替。

### 0.3 顺序范围

- 只保证同一流内 `(代数, seq)` 顺序；行情流与账户变动流之间不排序、不对齐时间（`uta-design.md:224-228`）。
- 同一账户（同子账户）的写按批准顺序递送；跨账户互不等待（R2）。
- 帐票只追加且不可变；引用只能指向已存在的帐票（`uta-design.md:185`）。

## 1. 契约 A：集成 ↔ 核心

契约 A 的 RPC 由核心和集成双方调用。下文“核心 → 集成”表示核心发起；“集成 → 核心”表示集成发起。集成不提交指令或决定，不自行发起交易（`uta-design.md:245`）。

### A-01 集成会话建立与能力声明

**方向**：集成 → 核心；核心 → 集成返回结果。

**发起者**：集成进程，在传输认证得到 `Integration(AccountId)` 后发起。

**前置**：传输认证已完成；请求来自该账户的集成会话；能力声明覆盖 §2.8 的全部项目。核心先校验声明，完备后才接受会话（`uta-design.md:233-241`）。

**请求字段**：

- 会话认证得到的集成身份与账户范围（不在请求体重复携带）。
- `集成会话号`：来自当前传输认证会话，用作能力声明幂等键。
- `指令能力[]`：每个委托、改单、撤单、平仓的支持与否；client key 是否有 broker 文档化幂等语义；client key 回读、未成交列表、成交/持仓对账三个查询渠道各自是否存在及其可信结论；状态回票字段能力与成交回票字段能力逐项声明；`逐笔成交：有 / 无` 必须明确声明。
- `读能力[]`：账户、持仓、订单、报价、合约搜索、合约详情、衍生品发现、盘口、市场时钟、历史 bar、钱包、历史记录各自的支持与返回字段；返回字段逐项声明支持或明确 unavailable。
- `流能力[]`：行情记录流与账户变动流各自的支持与否、续传游标有无、配额、是否可暂停。
- `历史 bar 能力`：支持与否、pacing。
- `子账户枚举能力`。
- `状态映射表版本`：值为集成制品版本字符串。

**同会话重复声明**：以 `集成会话号` 去重；同一会话号再次声明时整体替换能力声明，不产生新的能力帐票。能力缩减会使受影响订阅挂起并通知。

**结果 ADT**：

- `能力已接受`：核心完成校验并接受集成会话。
- `能力声明不完备而拒绝`：核心校验发现 §2.8 声明不完备。
- `集成会话无权而拒绝`：已认证身份不具备该账户集成范围；同时记安全事件。未认证连接是直接断开，不编码为结果分支。

**幂等键**：`集成会话号`。同一会话号重复声明整体替换；新会话号表示会话重建，按能力声明重新校验。

**顺序保证**：只有 `能力已接受` 后，核心才向该集成发送 A-02、A-09、A-10、A-11，且集成才可发起 A-03；能力变更的影响先于受影响流的后续处理。不同账户的会话互不等待。

**规则引用**：`uta-design.md:233-241`（能力声明）；`uta-design.md:243-245`（会话与权限）；Q13、Q16、Q18、Q19。

### A-02 接收已授权指令

**方向**：核心 → 集成；集成 → 核心返回接收结果。

**发起者**：核心，在指令已有批准决定并按账户队列递送时发起。

**前置**：集成会话已被 A-01 接受；指令已经过核心权限与参数校验；指令已有批准决定；该账户队列允许递送。集成只接收核心已授权指令。

**请求字段**：

- `InstructionId`、账户、客户端幂等键。
- 可选 `sub_account_id`；请求指定子账户时，核心按目标账户已接受的子账户能力校验；未枚举子账户能力而仍指定时，按 R8 在创建期拒绝。
- 指令种类：委托、改单、撤单或平仓；改单/撤单的目标是指令或 broker 原生 id。
- `OrderRequest` 委托载荷：`Contract`、方向、数量、订单类型、价格和 broker.ts `Order` 中保留的订单字段；数量与价格均为 decimal 字符串；委托可带 TP-SL。
- `ModifyPayload` / `CancelPayload`：目标与变更字段按 `OrderRequest` 的命名字段承载；撤单可带 `OrderCancel`；目标不明时不应进入本操作。`ClosePayload` 携带 `Contract`、可选 `sub_account_id` 与可选数量，缺失数量表示全量平仓。
- `尝试号`。

**结果 ADT**：

- `指令已接收`：集成记录该指令与尝试号，等待调用许可。

若集成会话在接收前断开，传输没有此业务结果；核心按重启规则处理“已交集成”而非假定已调用 broker。

**幂等键**：集成按 `(指令 id, 尝试号)` 去重；同一指令在“已交集成”阶段可以重复投递，同一尝试号不得导致多次 broker 调用（R1）。

**顺序保证**：同一账户按批准顺序递送；跨账户互不等待；同一流的事件顺序由流规则另行保证。

**规则引用**：`uta-design.md:202-204`（R1、R2、R3）；`uta-design.md:196`；Q2、Q4、Q7。

### A-03 请求调用许可与许可确认

**方向**：集成 → 核心请求调用许可；核心 → 集成返回许可确认或拒绝。

**发起者**：集成，在准备调用 broker 前发起。

**前置**：A-02 已收到同一指令与尝试号；集成会话仍有效；集成使用的 broker SDK/HTTP 客户端已关闭写请求自动重试。核心尚未为该尝试号落盘调用许可。

**请求字段**：

- `指令 id`。
- `尝试号`。
- `账户`。
- `集成会话号`：由当前传输认证上下文提供，写入许可绑定，不由请求体伪造。
- `请求摘要`：`sha256` over 规范化后的指令载荷（字段排序、decimal 规范形）。

**结果 ADT**：

- `调用许可已确认`：核心已先落盘绑定 `指令 id + 尝试号 + 账户 + 集成会话号 + 请求摘要` 的许可；确认带该集成会话号，集成只接受当前会话号的确认，收到确认后才调用 broker，且同一许可只调用一次。
- `同尝试号摘要不一致而拒绝`：同一尝试号已有不同请求摘要，核心拒绝。
- `同尝试号已有许可而拒绝`：该尝试号的许可已经落盘，核心不再向任何集成实例发放新的许可。

没有收到 `调用许可已确认` 不是另一个结果分支：当前集成实例收到非本会话的确认时丢弃、不调用 broker；会话断开时丢弃待发项。核心不承诺仍存活的旧集成实例不会晚读到自己会话的合法确认并调用 broker；安全只依赖许可落盘即该尝试“可能已调用”、核心永不向任何集成实例再许可同一尝试、该账户队头阻塞（R2）。旧实例晚调用产生的回票按 R11 关联到同一尝试。许可落盘后核心侧进入结果不明；重新派发使用新尝试号，不留独立帐票。

**幂等键**：`(指令 id, 尝试号)`；请求摘要必须与已落盘摘要相同才可能识别为同一请求，但已有许可仍不得再次许可。

**顺序保证**：许可落盘先于许可确认，许可确认先于 broker 调用；许可落盘后同一尝试号永不再许可；结果不明期间不创建新的 broker 尝试。只有能力声明中 broker 文档化保证同一 client key 幂等时，才可按该能力规则重放同一尝试；这属于 A-09 查询渠道，不是通用自动重试。

**规则引用**：`uta-design.md:202`（R1 先许可后调用）；`uta-design.md:204`（R3 不明不重发）；`uta-design.md:131`、`uta-design.md:133`；Q2、Q4、Q7。

### A-04 提交回票

**方向**：集成 → 核心；核心 → 集成返回记录结果。

**发起者**：集成，在 broker 返回受理、成交、状态或集成收到 broker 事件时发起。

**前置**：A-01 会话已接受；事件来自该集成账户；回票载荷严格二选一且不可缺失；状态回票按 broker 原生 id 或声明可靠的 client key 提供可关联线索，成交回票必须提供 broker 成交 id。集成不能替核心虚构指令引用。

**请求字段**：

- 账户、可选的 `broker 原生 id`；若能力声明允许，提供 `client key`。broker 已分配原生 id 时必须提供；未分配时不填数字观察值替代。
- `回票载荷`（严格 oneof）：
  - `状态回票`：状态原值、映射状态、累计成交量、剩余、平均成交价；可带 broker 原生 id、client key、broker 时间、原始负载摘要与状态扩展。
  - `成交回票`：broker 成交 id、单笔数量、单笔价格、佣金（若已到达）、broker 时间；并保留 `Execution.ts` 与 `CommissionAndFeesReport` 的全部叶字段。成交回票可带关联的 broker 原生 id、client key、原始负载摘要与扩展。
- 状态回票去重键二选一：`broker 事件 id`，或指纹 `(broker 原生 id, 状态原值, 累计成交量)`；指纹不含时间戳，并在提交账户范围内比较；没有 broker 原生 id 时不能使用指纹。
- 成交回票去重键：`broker 成交 id`；缺少该 id 时不能生成成交回票。

**结果 ADT**：

- `回票已关联`：核心按 broker 原生 id 或可靠 client key 关联到指令并追加对应状态回票或成交回票。
- `回票记为外部变动`：找不到指令，或指令已经终态；核心按 A-06 追加外部变动，不改任何指令状态。
- `重复状态回票已忽略`：同 broker 事件 id 或同状态指纹已存在，核心不追加第二张相同状态回票。
- `重复成交回票已忽略`：同 broker 成交 id 再到且单笔数量、单笔价格相同，核心不追加第二张成交回票。
- `佣金补录已记录`：同 broker 成交 id 的既有成交回票佣金从无到有；核心追加 `佣金补录` 帐票并引用该成交 id，不改原成交回票。
- `成交冲突已记录并告警`：同 broker 成交 id 的单笔数量或单笔价格不同；两张成交回票都保留，并追加 `成交冲突` 帐票与告警。
- `因缺少状态回票去重键而拒绝`：状态回票没有 broker 事件 id，且没有可用状态指纹；不追加帐票、不进入账户变动流。
- `因缺少 broker 成交 id 而拒绝`：成交回票没有 broker 成交 id；不追加帐票、不进入账户变动流，并计入本会话被拒记录数。
- `因能力声明无逐笔成交而拒绝`：能力声明为 `逐笔成交：无` 却提交成交回票；不追加帐票、不进入账户变动流，并计入本会话被拒记录数。
- `因回票载荷缺失而拒绝`：请求没有状态回票或成交回票；不追加帐票。

**幂等键**：状态回票使用 broker 事件 id，或没有事件 id 时使用指纹 `(broker 原生 id, 状态原值, 累计成交量)`；成交回票使用 broker 成交 id。佣金补录与成交冲突均引用 broker 成交 id，不另造替代键。

**顺序保证**：同一账户变动流按 `(代数, seq)` 发出；状态回票按 broker 状态偏序单调折叠，迟到旧状态不覆盖新状态；成交回票逐笔追加且不改变指令状态；佣金补录和成交冲突在对应成交回票之后追加；不同流不排序。

**规则引用**：`uta-design.md:41`；`uta-design.md:179-180`；`uta-design.md:199`；`uta-design.md:205-207`（R4、R5）；`uta-design.md:218-220`；`uta-design.md:289`；Q1、Q5、Q6。

### A-05 提交对账响应

**方向**：集成 → 核心；核心 → 集成返回记录结果。

**发起者**：集成，在 broker 返回持仓、订单列表、账户或结果不明查询的回读结果时发起。

**前置**：A-01 会话已接受；响应属于该集成账户；若响应是结果不明查询的回读，包含被查询指令的关联线索。

**请求字段**：

- 账户与数据时点。
- 对账响应种类：持仓、订单列表、账户、回读结果。
- 对账响应内容：持仓为 `Position[]`，订单列表为 `OpenOrder[]`，账户为 `AccountInfo`，回读结果为 `ReadPayload` 中可关联的回读结构；数量、价格等 decimal 字段为字符串。
- 对账响应键：`(账户, 种类, 集成会话号, 集成序号)`。
- 回读结果关联的指令 id、尝试号、broker 原生 id 或 client key（有则提供）。

**结果 ADT**：

- `对账响应已记录`：核心按对账响应键追加对账响应帐票；持仓、订单列表、账户响应进入账户变动流。
- `重复对账响应无操作`：同一对账响应键已存在，不追加第二张帐票，不改变任何指令状态。

**幂等键**：`(账户, 种类, 集成会话号, 集成序号)`；同键重复是无操作。

**顺序保证**：同一账户变动流内按 `(代数, seq)`；对账响应不改变不相干指令状态；关联结果不回写既有不可变帐票。

### A-06 提交外部变动

**方向**：集成 → 核心；核心 → 集成返回记录结果。

**发起者**：集成，在 broker 事件或对账响应无法关联任何本地指令时发起。

**前置**：A-01 会话已接受；事件属于该集成账户；集成不能找到匹配的 broker 原生 id 或可靠 client key，或匹配指令已经终态。

**请求字段**：
- 账户、可选的 `broker 原生 id`；broker 已分配原生 id 时必须提供，未分配时由能力字段标明 unavailable。
- 状态原值、累计成交量与原始负载摘要；若有则保留状态扩展。外部变动不接收成交回票载荷。
- 状态回票去重键为 broker 事件 id，或指纹 `(broker 原生 id, 状态原值, 累计成交量)`；二者至少一个必须提供，指纹不含 broker 时间且没有原生 id 时只能使用事件 id。
- 不能关联的说明；若存在结果不明指令，标明“存在未定指令”。该标记不引用指令，也不把变动归因给它。

**结果 ADT**：

- `外部变动已记录`：核心追加外部变动帐票并进入账户变动流。
- `因缺少外部变动去重键而拒绝`：事件 id 与状态指纹均未提供；不追加外部变动、不进入账户变动流。

**幂等键**：broker 事件 id；若没有事件 id，则使用状态指纹 `(broker 原生 id, 状态原值, 累计成交量)`。二者都未提供时返回 `因缺少外部变动去重键而拒绝`。

**顺序保证**：外部变动不改变任何指令状态；同一账户变动流按 `(代数, seq)`；结果不明收敛后不回改这张不可变帐票。

**规则引用**：`uta-design.md:218-220`；`uta-design.md:179`；Q6。

### A-07 提交行情记录

**方向**：集成 → 核心；核心 → 集成返回记录结果。

**发起者**：集成，在收到 broker 行情或历史 bar 页中的行情记录后发起。

**前置**：A-01 会话已接受；对应行情来源和流已在能力声明中接受；记录具有来源内的代数与 seq。

**请求字段**：

- `SourceId`、流种类、`代数`、`seq`。
- 行情记录；`instrument` 用带来源前缀的 `aliceId`。
- 历史 bar 的 quality / freshness（若记录是历史 bar）。

**结果 ADT**：

- `行情记录已记录`：核心按 `(代数, seq)` 追加来源内记录。

**幂等键**：v2 没有单独的行情记录幂等键；`(流, 代数, seq)` 是记录位置，不另加键。

**顺序保证**：同一流同代数 seq 连续；来源之间不排序、不对齐时间、不合并；断裂时先有来源缺口再进入新代数的记录。

**规则引用**：`uta-design.md:49-56`；`uta-design.md:222-228`；Q11、Q14、Q18。

### A-08 报告续接

**方向**：集成 → 核心；核心 → 集成返回接收结果。

**发起者**：集成在重连后、发送新一段行情记录前发起。

**前置**：A-01 会话已接受；集成已判断 broker 是否提供可信续传游标；报告针对明确的来源和流。

**请求字段**：

- `SourceId` 与流种类。
- 续接判断二选一：`能续接`；或 `不能续接`，并提供前一代数、前一段最后 seq、原因。
- 能续接时提供集成侧续传游标 `opaque bytes`；核心只存储、不解释。
- 不能续接的原因只能是 v2 已列出的来源缺口原因：断线且无续传游标、配额剥夺、入口溢出。

**结果 ADT**：

- `续接报告已记录`：核心接受报告。能续接时继续同一代数；不能续接时建立新代数，并要求新代数首条为投递缺口。

**幂等键**：同一集成会话、来源、代数与集成侧游标重复报告无新增记录；游标内容 opaque，核心不解释。

**顺序保证**：不能续接的报告先于新代数首条投递缺口；缺口先于新代数后续行情记录；跨来源不排序。

**规则引用**：`uta-design.md:224-226`；`uta-design.md:241`；Q11、Q14、Q18。

### A-09 结果不明查询要求与回答

**方向**：核心 → 集成发查询要求；集成 → 核心返回回答。

**发起者**：核心，在某指令已有调用许可但没有确定回票时，按能力声明依次发起。

**前置**：该指令存在已落盘调用许可；没有确定回票；核心已按 `(broker, 指令种类)` 选择声明为可信的查询渠道。结果不明期间不创建新的 broker 尝试。

**请求字段**：

- 指令 id、尝试号、账户。
- 当前查询渠道三选一且按顺序发送：client key 回读、未成交列表、成交/持仓对账。
- 查询所需的 client key、broker 原生 id 或 `InstructionFeatures`；后者严格覆盖请求摘要中的 instrument、方向、数量、价格、类型、提交时间。

**结果 ADT**：

- `查到回票`：集成返回可关联回票，核心补回票并关联到指令。
- `证明未递`：集成返回 broker 明确答复，且对应能力声明证明该答复可信；核心追加未递记录，不自动重下。
- `仍无结论`：渠道没有给出可证明结论；核心继续下一渠道，渠道用尽后转人工并等待人工凭证。

集成不能用未声明或不可信的答复产生 `证明未递`。

**幂等键**：查询要求按 `(指令 id, 尝试号, 查询渠道)` 识别；`InstructionFeatures` 不另造字段。

**顺序保证**：严格按 client key 回读 → 未成交列表 → 成交/持仓对账；未得结论不发新的调用许可；查到的回票进入账户变动流。

**规则引用**：`uta-design.md:43`；`uta-design.md:202-204`；`uta-design.md:210-216`；Q2、Q3、Q7。

### A-10 一次性读转发

**方向**：核心 → 集成发读要求；集成 → 核心返回响应或 typed 失败。

**发起者**：核心，在契约 B 的一次性读完成目标解析与权限判定后，按账户逐一转发。

**前置**：A-01 会话已接受；目标账户已由核心解析和授权；请求在传输 deadline 内；历史 bar 只有能力声明支持时才转发。

**请求字段**：

- 一个已授权账户。
- N3 的读种类：账户、持仓、订单、报价、衍生品发现、盘口、市场时钟、历史 bar、合约搜索、合约详情、钱包、历史记录。
- 已由核心完成 N2 解析的读目标与读条件；`ReadQuery` 使用命名字段承载 `aliceId`、子账户、合约、搜索模式和 bar 条件，不使用未命名载荷。

**结果 ADT**：

- `读响应`：带来源与数据时刻；账户为 `AccountInfo`，持仓为 `Position[]`，订单为 `OpenOrder[]`，合约搜索/详情为 `Contract`，报价为 `Quote`，市场时钟为 `MarketClock`，历史 bar 为 `Bar[]`，其他种类使用对应命名响应；历史 bar 另带 quality / freshness。
- `不可用`。
- `未找到`。
- `不支持`。
- `超时`。

集成按一个账户返回一个结果；核心不合并、不重排。持仓、订单列表、账户的读响应同时作为对账响应留票并进入账户变动流；报价、盘口、搜索、时钟、历史 bar 等不留票。

**幂等键**：v2 未定义一次性读的独立幂等键；同一读可由 deadline 结束，不把读超时转成写状态。

**顺序保证**：同一批 fan-out 的账户结果互相独立；返回顺序不承担跨账户排序语义；单次读只选一个来源路径。

**规则引用**：`uta-design.md:49-56`；`uta-design.md:114-121`；`uta-design.md:230-231`；Q15、Q16。

### A-11 回填页

**方向**：核心 → 集成发历史 bar 回填要求；集成 → 核心返回回填结果。

**发起者**：核心，在客户端订阅含回填且能力声明允许历史 bar 时发起。

**前置**：对应订阅已接受；历史 bar 能力支持且 pacing 可用；目标来源、instrument 与代数已确定。

**请求字段**：
- 来源、流、代数与 instrument 的 `aliceId`。
- 回填所需的历史 bar 条件与声明的回填窗口起点。
- 集成侧下一页游标：`opaque bytes`；核心只存储、不解释。

**结果 ADT**：

- `回填页`：返回 `{记录[], 集成侧下一页游标 opaque, 是否最后一页}`；记录进入同一流。
- `不支持`：只有能力声明不支持历史 bar 时的 typed 结果；正常流程在前置阶段应拒绝发起。

核心按 pacing 拉页；`是否最后一页`为真后只发一次就绪通知。断代后按声明的回填窗口起点重新回填；回填与实时进入同一流，同一代数内按 `(代数, seq)` 去重。

**幂等键**：页游标由集成提供且 opaque；同一流的 `(代数, seq)` 负责边界去重。

**顺序保证**：回填页记录先于该订阅的 live 记录；回填/实时共享流顺序；断线后新代数从声明窗口起点重来；来源之间不排序。

**规则引用**：`uta-design.md:222-228`；`uta-design.md:143`；Q11、Q14、Q16。

## 2. 契约 B：客户端 ↔ 核心

### B-01 客户端会话建立

**方向**：客户端 → 核心；核心 → 客户端返回结果。

**发起者**：客户端，在传输认证完成后发起。

**前置**：传输认证得到 `Client(名称)` 或授权的 `Human(名称)`；请求体不得携带伪造身份。未认证连接直接断开并记安全事件。

**请求字段**：

- 会话认证上下文；身份、账户范围和用途不在请求体重复携带。

**结果 ADT**：

- `会话已建立`。
- `客户端会话无权而拒绝`：已认证身份没有核心策略给予的范围；同时记安全事件。未认证连接是直接断开，不编码为结果分支。

**幂等键**：v2 未定义会话建立的业务幂等键；传输连接不是指令幂等键。

**顺序保证**：会话建立后才能调用 B-02 至 B-14；客户端断线不删除核心持有的订阅。

**规则引用**：`uta-design.md:169`；`uta-design.md:243-245`；Q17、Q19、Q20、Q21。

### B-02 一次性读

**方向**：客户端 → 核心请求；核心 → 客户端返回逐账户结果。

**发起者**：客户端。

**前置**：B-01 会话已建立；核心按会话身份、账户用途和策略授权读；请求有 deadline。

**请求字段**：

- N2 读目标四选一：精确 source、provider 前缀、无 source 的全账户 fan-out、trading-only 过滤。
- N3 读种类：账户、持仓、订单、报价、衍生品发现、盘口、市场时钟、历史 bar、合约搜索、合约详情、钱包、历史记录。
- `aliceId`、账户选择、子账户和读条件按所选路径提供；字段与返回类型按 A-10 的命名载荷。

**结果 ADT**：

- `逐账户读成功`：每个账户独立携带来源、数据时刻和读响应；历史 bar 带 quality / freshness。
- `逐账户不可用`。
- `逐账户未找到`。
- `逐账户不支持`。
- `逐账户超时`。

fan-out 的一个账户失败不影响其他账户；核心不合并、不重排；客户端可保留上次数据并标 stale。持仓、订单列表、账户结果同时收到对账响应帐票；其余读结果不留票。

**幂等键**：v2 未定义读请求幂等键；读结果不创建新的指令或调用许可。

**顺序保证**：逐账户独立；一次读只选一个来源路径；不承诺跨账户或跨来源顺序。

### B-03 订阅

**方向**：客户端 → 核心；核心 → 客户端返回接纳或 typed 拒绝。

**发起者**：客户端。

**前置**：B-01 会话已建立；客户端对选择器和账户有订阅权限；核心按 A-01 的流能力与配额判断整体接纳或拒绝。

**请求字段**：

- 选择器：行情流按 instrument；账户变动流按账户。
- 所需流种类、instrument 的 `aliceId`、账户范围。
- 是否要求回填及回填窗口起点与条件。
- 客户端当前每流游标（若要续接）：`(流, 代数, seq)`；这是客户端游标，与集成侧 opaque 游标分开。

**结果 ADT**：

- `订阅已接纳`：核心持有 `Subscription(客户端身份, 选择器, 每流游标, 状态=活跃)`。
- `订阅因能力不支持而拒绝`。
- `订阅因配额而拒绝`：已有订阅不受影响。

订阅状态只有 `活跃` 或 `挂起(原因)`。能力缩减或集成会话消失时保留游标、挂起并发送挂起通知；条件恢复时自动恢复并发送恢复通知，不需重新订阅。退订后删除游标、回填进度和待确认缺口；再次订阅是新订阅，从当前 seq 或声明窗口起点重新开始。

**幂等键**：v2 未定义订阅的独立键；订阅由客户端身份、选择器和每流游标组成。

**顺序保证**：接纳或拒绝是整体结果，不部分接纳；接纳后只保证每个流内顺序；断线不删除订阅。

### B-04 退订

**方向**：客户端 → 核心；核心 → 客户端返回结果。

**发起者**：客户端。

**前置**：B-01 会话已建立；会话身份拥有目标订阅；请求选择器唯一确定目标订阅。

**请求字段**：

- 订阅客户端身份来自会话。
- 选择器、流种类与账户或 instrument。

**结果 ADT**：

- `订阅已退订`：核心从订阅表整体原子替换中移除目标订阅；同时删除其游标、回填进度和待确认缺口。
- 目标不存在时同样返回 `订阅已退订`，不产生额外失败分支。

**幂等键**：选择器、流种类与会话身份；重复退订（包括目标已经不存在）幂等成功。

**顺序保证**：退订在同一订阅的后续投递前生效；其他客户端和其他流不受影响。

**规则引用**：`uta-design.md:225-227`；`uta-design.md:308`。

### B-05 投递流

**方向**：核心 → 客户端推送；客户端以 B-06/B-07 确认。

**发起者**：客户端建立投递流后由核心推送。

**前置**：B-01 会话已建立；B-03 订阅已接纳；核心已恢复订阅与游标，或已按 A-08/A-11 形成当前代数。

**请求字段**：

- 投递流建立时的订阅选择器与客户端每流游标 `(流, 代数, seq)`。
- 后续事件不由客户端逐条请求；事件带来源流、代数、seq。

**结果 ADT**：每一条投递是一个 `DeliveryEvent`：

- `行情记录`。
- `账户变动帐票`：回票、对账响应、外部变动、递送进度。
- `投递缺口`：来源连续性断裂或慢消费者缓冲缺口，带原因及范围。
- `挂起通知`：订阅进入挂起，带原因；游标保留。
- `恢复通知`：集成重新声明支持或会话重建后自动恢复。
- `就绪通知`：回填完成、从 backfilling 进入 live，只出现一次。

**幂等键**：客户端按 `(流, seq)` ack；投递缺口按 `(流, from seq, to seq)` 确认。

**顺序保证**：每流至少一次；慢消费者缓冲满时先发投递缺口并停投该流，直到 B-07 确认缺口；挂起时停投该流，恢复后从保留游标继续；其他流和其他客户端不因慢者或挂起而停投。跨流不排序。

### B-06 确认投递

**方向**：客户端 → 核心；核心 → 客户端返回确认结果。

**发起者**：客户端。

**前置**：B-01 会话已建立；B-03 订阅已接纳；确认的 `(流, seq)` 来自已投递事件且尚未被同一客户端确认。

**请求字段**：

- 流、代数、seq。
- 订阅客户端身份来自会话。

**结果 ADT**：

- `投递已确认`：核心更新该流游标并持久化订阅表。

**幂等键**：`(流, seq)`。

**顺序保证**：同一流按 seq 确认；确认不改变其他流；客户端可以按至少一次语义重复处理同一记录。

**规则引用**：`uta-design.md:225-227`；`uta-design.md:308`；Q11、Q12、Q17。

### B-07 确认投递缺口

**方向**：客户端 → 核心；核心 → 客户端返回确认结果。

**发起者**：客户端，在收到投递缺口后发起。

**前置**：B-01 会话已建立；B-05 已发送该流的投递缺口；请求的 from/to seq 与缺口一致。

**请求字段**：

- 流、代数、`from seq`、`to seq`。
- 缺口原因（核心发送的原因原样确认，不由客户端改写）。

**结果 ADT**：

- `投递缺口已确认`：核心解除该流停投状态，并按当前规则继续投递。

**幂等键**：`(流, from seq, to seq)`。

**顺序保证**：缺口确认之前该流停投；确认不替代来源缺口，也不改变其他流顺序。

**规则引用**：`uta-design.md:224-227`；Q11、Q12、Q14。

### B-08 提交指令

**方向**：客户端 → 核心；核心 → 客户端返回指令结果。

**发起者**：客户端，或经授权的 Human 身份通过客户端边界发起。

**前置**：B-01 会话已建立；核心校验账户用途、身份、策略、账户归属和指令参数；可交易账户和 `allowAiTrading`/人工审批策略满足要求。请求体不携带身份。

**请求字段**：
- 目标账户。
- 可选 `sub_account_id`；指定时必须被目标账户的子账户能力枚举并与合约匹配；能力未枚举子账户却指定时，按 R8 创建期拒绝。
- 客户端幂等键。
- 指令种类：委托、改单、撤单或平仓；改单/撤单的目标是目标指令或 broker 原生 id。
- `OrderRequest`、`ModifyPayload`、`CancelPayload` 或 `ClosePayload` 指令载荷：`Contract`、方向、数量、订单类型、价格、有效期、TP-SL 及 broker.ts `Order` 中保留的字段；数量与价格均为 decimal 字符串。

**结果 ADT**：

- `指令已保留`：返回 `InstructionId`；同一账户同一客户端幂等键重复时返回同一指令，不新建第二条。
- `创建期拒绝`：返回已落盘的 `InstructionId` 与一次落盘的否决决定，拒绝原因是 `instrument 不属于目标账户`、`指定子账户未被能力声明枚举`、`指定子账户与合约不匹配`、`数量为零或 NaN`、`账户只读`、`策略权限` 或 `目标结果不明`；目标结果不明时不排队，客户端应在目标收敛后重新提交。

创建期拒绝的权限类原因另记安全事件，参数类原因不记；所有创建期拒绝都不递送 broker。`指令已保留` 不代表已递送 broker；决定、递送进度与回票通过后续帐票和投递流可见。客户端 deadline 到期不改变已经递出的指令。

**幂等键**：`(目标账户, 客户端幂等键)`。

**顺序保证**：同一账户的已批准指令按批准顺序递送；跨账户互不等待；核心先保留指令再交集成。

**规则引用**：`uta-design.md:167`；`uta-design.md:187-210`；`uta-design.md:243-245`；Q1、Q4、Q7、Q8、Q9。

### B-09 提交决定（带期望版本）

**方向**：客户端 → 核心；核心 → 客户端返回决定结果。

**发起者**：拥有决定权限的 Human、Core 或经规则授权的请求路径。

**前置**：B-01 会话已建立；会话身份拥有该指令的决定权限；指令存在；期望版本等于该指令当前帐票数，且仍在批准前等待 deadline 内。

**请求字段**：
- 指令 id。
- 期望版本 = 当前帐票数。
- 客户端提供的决定 token（永不复用）。
- 决定：批准或否决。过期由核心按 R7 产生过期记录，不由客户端伪造。

**结果 ADT**：

- `决定已记录`：追加批准或否决决定；同 token 同内容重复提交返回既有决定记录。
- `因期望版本不匹配而冲突`：追加冲突记录，不改指令状态。
- `因批准前等待已过期而记录过期`：追加独立的过期决定，终态显示“过期”，不递送该指令。
- `因决定 token 内容冲突而拒绝`：同 token 不同内容，不追加第二条决定。
- `因没有决定权限而拒绝`。

**幂等键**：客户端决定 token；token 永不复用；同 token 同内容返回既有记录，同 token 不同内容返回冲突。

**顺序保证**：决定先于该指令递送；版本冲突或 token 冲突不改状态；同一账户按批准顺序递送。

**规则引用**：`uta-design.md:176-178`；`uta-design.md:193-210`（R6、R7、R8、R9）；Q9、Q10。

### B-10 提交人工凭证

**方向**：Human → 核心；核心 → Human 所在客户端返回记录结果。

**发起者**：Human 身份。

**前置**：B-01 会话认证为 Human；目标指令处于需要人工收敛的结果不明或人工审批路径；请求说明结论与依据。

**请求字段**：
- 指令 id、尝试号。
- 客户端提供的凭证 token（永不复用）。
- 人工结论二选一：`已递`（带 broker 原生 id、状态）或 `未递`。
- 依据。

**结果 ADT**：

- `人工凭证已记录`：追加不可变人工凭证；已递按凭证状态继续接回票，未递成为终态；同 token 同内容重复提交返回既有凭证记录。
- `因凭证 token 内容冲突而拒绝`：同 token 不同内容，不追加第二条凭证。
- `因会话身份不是 Human 而拒绝`。

**幂等键**：客户端凭证 token；token 永不复用；同 token 同内容返回既有记录，同 token 不同内容返回冲突。

**顺序保证**：人工凭证只能引用已存在指令和帐票；结果不明关闭前不发新的调用许可；凭证不回改既有帐票。回票为 broker 事实；凭证后到达且与其结论不一致时，按 R10 追加 `人工结论与回票不一致` 帐票并告警，以回票结果为准，不再查询。

### B-11 读取指令视图

**方向**：客户端 → 核心；核心 → 客户端返回指令视图。

**发起者**：客户端。

**前置**：B-01 会话已建立；会话身份有目标账户与指令的读权限。

**请求字段**：

- 指令 id。

**结果 ADT**：

- `指令视图已找到`：按指令持有的帐票计算状态，返回指令、决定、递送进度、状态回票、成交回票、佣金补录、成交冲突、对账响应关联、人工凭证及 `人工结论与回票不一致` 帐票可见部分；成交回票不参与状态计算。

**幂等键**：指令 id。

**顺序保证**：返回的是已持久化帐票的函数；同一读不创建新帐票；视图不改变帐票。

**规则引用**：`uta-design.md:167`；`uta-design.md:187-208`；Q1、Q2、Q3、Q5、Q9、Q10。

### B-12 读取账户帐票

**方向**：客户端 → 核心；核心 → 客户端返回帐票读取结果。

**发起者**：客户端。

**前置**：B-01 会话已建立；会话身份有目标账户的读权限。

**请求字段**：
- 目标账户。
- 帐票种类：指令、决定、递送进度、状态回票、成交回票、佣金补录、成交冲突、对账响应、外部变动、人工凭证、缺口、`未映射状态` 及 `人工结论与回票不一致`。
- `(代数, seq)` 读取区间：起点与终点；按账户变动流追加顺序返回。
- 分页游标：上一页最后一条记录的 `seq`；无游标表示从区间起点开始。

**结果 ADT**：

- `帐票已找到`：返回所选帐票，保持追加顺序与引用关系，并返回下一页游标（本页最后一条 seq）。
- `帐票未找到`。

**幂等键**：目标账户、帐票种类、读取区间与分页游标。

**顺序保证**：按账户变动流和帐票追加顺序返回；不重排、不修改、不回写帐票。

**规则引用**：`uta-design.md:172-185`；`uta-design.md:218-228`；Q3、Q6、Q9、Q17。

### B-13 健康读

**方向**：客户端 → 核心；核心 → 客户端返回健康结果。

**发起者**：客户端或健康探测方。

**前置**：传输认证与 B-01 会话完成；健康探测必须快速。

**请求字段**：
- 无业务字段；身份来自会话。

**结果 ADT**：

- `健康读已返回`：按账户返回 `集成会话是否建立`、`能力声明版本`、`最近一条帐票时间`、`最近一条行情记录时间`、`当前挂起的订阅数`、`本会话被拒记录数`（无去重键或违反 `逐笔成交：无` 能力声明的提交）。

健康读不增加其他派生状态；启动、迁移和双实例诊断仍在传输/进程边界观察。

**幂等键**：无。

**顺序保证**：不参与指令、流或帐票顺序；不改变任何状态。

**规则引用**：`uta-design.md:123`；`uta-design.md:249-252`；Q17、Q20、Q21。

### B-14 能力读

**方向**：客户端 → 核心；核心 → 客户端返回能力声明。

**发起者**：客户端。

**前置**：B-01 会话已建立；会话身份有能力读取权限。

**请求字段**：
- 目标账户或公共行情来源；不携带流种类、读种类或指令种类筛选。

**结果 ADT**：

- `能力声明已返回`：返回当前完整能力声明，包括 §2.8 全部字段，不筛选、不合并。

**幂等键**：目标来源；v2 未定义独立业务幂等键。

**顺序保证**：返回当前已接受能力声明；能力缩减先影响订阅，再由后续读看到新声明。

**规则引用**：`uta-design.md:233-241`；`uta-design.md:245`；Q13、Q16、Q18。
