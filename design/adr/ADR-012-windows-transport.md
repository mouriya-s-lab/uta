# ADR-012 Windows 传输

## 状态
Provisional（X1）

## 背景
- K1 要求跨进程使用序列化文本或跨语言 RPC，并将 UTA 定位为独立二进制；F3 表明传输 deadline 到期时写请求仍可能已经到达 broker（`uta-design.md:81-84,100`）。
- N11 要求有界等待，N12 要求 Alice 侧使用跨语言序列化契约；Q19 要求未认证连接被拒绝、已认证但越权的控制请求被拒绝并记录（`uta-design.md:123-124,148-149`）。
- 当前平台约束只明确 macOS / Linux 使用 UDS，Windows 的传输仍需在命名管道与回环 TCP 加令牌之间验证（`uta-design.md:92,154`）。

## 决定
- Windows 传输暂不在两候选中定案；继续使用同一份 IDL 和契约 B，候选仅为命名管道或回环 TCP + 令牌（§3.4，`uta-design.md:351-353`）。
- 以 X1 的共同判据选择实现：1000 msg/s 下无死锁、断开可检测、非本用户进程被拒；实验通过前保持 Provisional，不把任一候选当作已验证决定（§6 X1，`uta-design.md:369-374`）。

## 被否决的替代
- 本决定没有列出允许集合中的其他替代项；主文档只保留上述两种 Windows 传输候选。

## 后果与验证
- 跨平台契约保持不变，代价是 Windows 实现和状态仍待实验，不得在实验前宣称传输安全性或性能已证明。
- X1 应分别在命名管道和回环 TCP + 令牌上观察 1000 msg/s 无死锁、断开可检测以及非本用户进程被拒；实验结果决定 ADR 状态是否可转为 Accepted（`uta-design.md:369-374`）。
- Q19 应在选定实现上复核认证、拒绝未认证连接和记录越权控制（`uta-design.md:148-149`）。
