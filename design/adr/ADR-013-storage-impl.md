# ADR-013 存储实现（手写分段追加 vs 现成库）

## 状态
Provisional（X2）

## 背景
- F3 表明写请求和回执可能分离，恢复所需的指令、许可和帐票边界必须依赖可靠持久化；N10 要求核心独立重启并恢复订阅（`uta-design.md:100,122-123`）。
- K8 要求副作用的消费与关联可安全表达；Q17 要求追加帐票和订阅表在 kill -9 后只留下完整记录（`uta-design.md:90,146-147`）。
- Q20 与 Q21 分别要求单写者接管以及格式迁移、断电后的两态结果，不能以未定义的半写状态继续服务（`uta-design.md:149-150`）。

## 决定
- 存储模块负责只追加记录、锁与 fence、版本与迁移以及写入确认，不负责业务规则；帐票一次写一条并更新索引，流记录按同流批次或单条缺口写入，订阅表整体原子替换（§3.3，`uta-design.md:340-349`）。
- 在手写分段追加与现成库之间暂不定案；索引可重建，跨记录顺序依靠先落盘再行动和幂等重做，不引入跨存储事务（§3.3，`uta-design.md:340-349`）。
- 以 X2 的崩溃矩阵决定实现：覆盖 torn write、fsync 前以及 rename 前后，并在三种文件系统上全部通过后才结束 Provisional 状态（§6 X2，`uta-design.md:369-375`）。

## 被否决的替代
- 每账户存折：按账户快照存储不能覆盖核心持有的帐票、流、订阅、能力和策略等记录类别及统一恢复边界。

## 后果与验证
- 两种实现候选都必须满足同一套记录、锁、版本和原子替换语义，代价是 X2 完成前不能宣称存储实现已确定。
- X2 应在三种文件系统的崩溃矩阵中证明 torn write、fsync 前和 rename 前后均恢复为旧版完整或新版完整；通过后才能将状态从 Provisional 改为 Accepted（`uta-design.md:369-375`）。
- Q17 应观察 kill -9 后没有半条帐票、订阅与游标可恢复；Q20/Q21 应观察锁接管与格式迁移的退出码、记录和断电结果（`uta-design.md:146-150`）。
