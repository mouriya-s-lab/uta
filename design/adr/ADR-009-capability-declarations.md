# ADR-009 能力声明决定能否下发、怎么查、订阅是否接受；不为 broker 假设能力

## 状态
Accepted

## 背景
- F4 规定能力、限额、幂等、回读和续传语义按 broker 与操作种类变化，且很多条目没有官方文档；F5 说明 broker 会限流，历史 bar 有 pacing；K3 要求核心消费集成洗过的、统一但可扩展的内部协议（`uta-design.md:85,101-102`）。
- N5 要求历史 bar 能力与质量元数据可见；N8 要求结果不明不自动重试；N9 要求只读和策略边界 fail-closed（`uta-design.md:117,120-122`）。
- Q3 要求按不同查询渠道收敛结果不明；Q13 要求按 broker 配额整体接受或拒绝订阅；Q16 要求能力不支持时返回 typed Unsupported（`uta-design.md:132,142,145`）。

## 决定
- 集成建立会话时声明指令、读、流、历史 bar、子账户和状态映射能力；核心校验完备声明后才接受会话，不为任何 broker 假设未声明能力（§2.8，`uta-design.md:238-246`）。
- 指令能力声明决定是否支持 client key 幂等、有哪些回读渠道及每个渠道的可信结论；核心据此决定能否下发和如何处理结果不明（§2.4、§2.8，`uta-design.md:215-221,238-246`）。
- 流能力声明决定续传游标、配额和暂停能力；能力缩减使受影响订阅挂起并通知，凭据切换或会话重建按读不可用、写遵守 R1 处理（§2.6、§2.8，`uta-design.md:227-246`）。

## 被否决的替代
- venue 词汇：它不能替代按 broker、操作种类和集成会话声明能力的精确模型。

## 后果与验证
- 核心不会把未声明的能力当作可用，代价是集成必须维护完整声明并在能力变化时触发挂起或重建。
- Q13 应观察超出声明配额的订阅在接纳时 typed 拒绝且不发送给集成；Q16 应观察不支持历史 bar 时返回 Unsupported；Q3 应观察只有声明为可信的查询渠道才能给出未递结论（`uta-design.md:132,142,145`）。
- X3 还需验证 200 条流、每秒 50 条消息及一名慢消费者下，快消费者 p99 不受影响；能力声明本身的可信性由 R-B 的契约测试 fixture 复核（`uta-design.md:375-378`）。
