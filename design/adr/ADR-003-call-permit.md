# ADR-003 调用许可是安全边界：先许可后调用，许可落盘即结果不明边界，不明不再许可

## 状态
Accepted

## 背景
- F3 表明写请求可能已经到达 broker，而调用方拿不到回执；N7 要求写的各阶段可见，N8 要求结果不明不能当作普通失败自动重试（`uta-design.md:100,119-120`）。
- Q2 描述调用许可落盘后核心在回票前崩溃，重启后必须判定结果不明且不再发放许可；Q4 描述许可前崩溃，集成未收到确认时不得调用（`uta-design.md:131-134`）。
- K8 要求副作用的消费和关联边界可安全定义（`uta-design.md:90`）。

## 决定
- 指令与“已交集成”先落盘；集成调用 broker 前向核心请求调用许可，核心将指令 id、尝试号、账户、集成会话和请求摘要一并落盘，确认后集成才可调用，而且同一许可只调用一次（R1，`uta-design.md:202-203`）。
- 许可是安全边界而不是调用事实：许可落盘后核心不能证明集成是否已调用；没有确定回票时，指令进入结果不明，且该尝试号永不再获得新的调用许可（R1，`uta-design.md:202-203`）。
- 核心重启会使旧会话确认失效；无许可的旧投递可用新尝试号重新派发，有许可的旧尝试直接进入结果不明，不再发放许可（R12、§2.10，`uta-design.md:213,252-257`）。

## 被否决的替代
- “两次确认=未递”：许可落盘后无法证明集成是否调用，不能由确认次数推出未递。
- 任何情况不重发：许可前崩溃时可证明未递，禁止重新派发会阻塞安全恢复。

## 后果与验证
- 先落盘再调用增加了持久化和会话状态，但把重复调用风险限定在一条已记录的许可边界内；结果不明必须交给 ADR-005 的收敛路径。
- Q2 应观察同一指令只有一条许可、fixture broker 调用记录至多一条，重启后进入结果不明且没有第二条许可；Q4 应观察调用记录为零且无许可记录（`uta-design.md:131-134`）。
- Q7 的不明变体还应证明结果不明期间后一笔不会取得新的调用许可（`uta-design.md:136-137`）。
