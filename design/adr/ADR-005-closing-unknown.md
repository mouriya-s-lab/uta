# ADR-005 结果不明只由回票 / 能力声明的查询 / 人工凭证关闭；集成 SDK 禁自动重试

## 状态
Accepted

## 背景
- F3 表明调用方可能拿不到已经到达 broker 的写回执；F4 表明查询渠道和幂等语义随 broker 与操作种类变化，不能由核心假设；K8 要求副作用的消费和关联边界可安全定义（`uta-design.md:90,100-102`）。
- N8 要求结果不明与冲突分开且不自动重试；N9 要求权限和策略边界在核心强制（`uta-design.md:120-122`）。
- Q3 要求分别验证 client key 回读、未成交列表和无查询渠道三种收敛结果；Q2 要求许可后崩溃进入查询而不再次发放许可（`uta-design.md:131-133`）。

## 决定
- 结果不明只按声明顺序使用 client key 回读、未成交列表、成交或持仓对账；查到则补回票，可信地证明未递则记录未递，无法证明时转人工（§2.4，`uta-design.md:215-221`）。
- 人工凭证只能由 Human 身份签发并说明结论与依据；回票与人工凭证冲突时以 broker 回票为准，保留人工凭证并追加不一致记录与告警（R10，`uta-design.md:211-212`）。
- 集成使用的 broker SDK 或 HTTP 客户端必须关闭写请求自动重试；只有能力声明明确 broker 对同一 client key 提供文档化幂等语义时，才可按该声明重放同一尝试（R1、R3，`uta-design.md:202-205`）。

## 被否决的替代
- 任何情况不重发：结果不明期间确实不得创建新 broker 尝试，但可证明未递的路径仍需由客户端发起新指令，不能以绝对禁令替代收敛规则。

## 后果与验证
- 结果不明不会被静默折叠为失败或成功，代价是无可信渠道时必须等待人工凭证；集成自动重试被关闭后，重复调用责任集中在声明过的幂等语义内。
- Q3 应分别观察回读补回票、列表查到补回票、无可信渠道转人工三种末态；人工态只能由带身份的人工凭证关闭（`uta-design.md:132-133`）。
- Q2 应证明重启后进入查询且许可数量不增加；Q5 应证明查询得到的回票仍保留原生字段并按单调规则折叠（`uta-design.md:131,134`）。
