# ADR-001 独立 Rust 进程；集成按账户独立进程；一份跨语言 RPC 契约

## 状态
Accepted

## 背景
- K1 要求 UTA 完全重写为独立进程和独立二进制，跨进程只用序列化文本或跨语言 RPC；K2 要求优先采用 Rust（`uta-design.md:81-85`）。
- K3 要求核心不处理 broker 协议，由集成转换为内部协议；K4 要求核心承担订阅后的 effect 分发，纯单线程不可接受（`uta-design.md:85-86`）。
- F4 表明能力、限额、幂等和回读语义按 broker 与操作种类变化；N10 要求 UTA 独立重启且客户端可重连（`uta-design.md:101-102,122-124`）。
- Q20 要求同一数据目录上的第二个核心拒绝启动，原持有者死亡后才能接管；Q19 要求认证连接与越权控制可被拒绝并记录（`uta-design.md:148-150`）。

## 决定
- 采用 Rust 编写独立核心进程；核心持有数据目录和全部记录，按每个配置账户运行独立集成进程，公共行情 feed 作为独立来源；一个账户的集成故障或凭据轮换不得影响同 broker 的其他账户（K1/K2、§3.1，`uta-design.md:81-92,305-324`）。
- 客户端只经契约 B 访问核心，核心与集成只经契约 A 通信；两份契约属于同一份跨语言 IDL，凭据只经启动环境注入，不经 RPC、也不写入日志（§3.1、§3.4，`uta-design.md:315-324,351-353`）。
- 传输实现遵循平台约束：macOS / Linux 使用 UDS；Windows 的具体传输留给 ADR-012 的实验，不在本决定中预设（§3.4，`uta-design.md:351-353,369-374`）。

## 被否决的替代
- 进程内集成插件：会把 broker 凭据、会话和故障隔离带入核心进程，违背按账户隔离的边界。

## 后果与验证
- 核心、客户端和集成拥有清晰的跨进程边界，集成可按账户独立重启，代价是需要维护契约 A/B 和进程监督。
- Q19 应证明未认证或越权请求不会改变配置或产生递送；Q20 应证明第二个核心因目录锁被拒、持有者死亡后可接管（`uta-design.md:148-150`）。
- ADR-012 的 X1 实验验证 Windows 候选传输在 1000 msg/s 下无死锁、能检测断开且拒绝非本用户进程；该实验尚未执行（`uta-design.md:369-374`）。
