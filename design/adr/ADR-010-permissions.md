# ADR-010 权限在核心一处强制；身份来自传输认证；fail-closed

## 状态
Accepted

## 背景
- N9 要求 read-only 账户、allowAiTrading 和人工审批在 UTA 边界强制；N12 要求 Alice 与 UTA 之间只有一份跨语言序列化契约；K8 要求副作用的消费和关联边界可安全定义（`uta-design.md:90,121-124`）。
- F6 表明子账户是某些 broker 的结构；F7 表明用户可以直接在 broker app 下单，UTA 只能事后看到（`uta-design.md:103-104`）。
- Q8 要求非法 instrument、数量和 read-only 下单在创建时拒绝且不递送；Q9 要求人工批准带身份、时间、依据和期望版本；Q19 要求伪造身份、未认证和越权控制都被拒绝并记录（`uta-design.md:137-139,148-149`）。

## 决定
- 权限在核心判定，依据传输认证得到的会话身份、账户用途（data-only / read-only / 可交易）和 Alice 策略；请求体不携带可替代会话身份的字段（§2.9，`uta-design.md:248-250`）。
- 核心统一执行指令创建校验、策略和人工审批边界；集成会话只能写回自己账户的帐票与行情，不能提交指令或决定（§2.9、§3.2，`uta-design.md:248-250,326-338`）。
- 策略或配置读取失败即拒绝；未认证连接直接断开并记安全事件，已认证但越权的请求拒绝并记安全事件（§2.9，`uta-design.md:248-250`）。

## 被否决的替代
- 核心内 WASM 程序宿主：把用户逻辑放进核心会绕过统一的会话身份和权限边界，不符合本轮核心只执行既定规则的范围。

## 后果与验证
- 权限判断只有一个强制入口，集成不能绕过核心代替客户端作决定；代价是每种身份、账户用途和策略都必须在会话范围中明确表达。
- Q8 应观察三笔非法请求各有指令与否决记录、fixture broker 调用为空，权限类另有安全事件；Q9 应观察批准与过期决定带完整身份和期望版本；Q19 应观察三种身份攻击均无递送和配置变更且有安全事件（`uta-design.md:137-139,148-149`）。
- Q6 应观察 broker 自行产生且无法关联的变动只记为外部变动，不被错误归因到客户端指令（`uta-design.md:135-136`）。
