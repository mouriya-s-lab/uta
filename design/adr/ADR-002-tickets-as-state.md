# ADR-002 状态是"手里有哪些帐票"的函数，帐票不可变只追加

## 状态
Accepted

## 背景
- F1 规定 broker 掌握交易事实，本地记录只是对它的解释；K8 要求明确副作用如何消费以及哪些对象可以关联（`uta-design.md:90,98-99`）。
- N7 要求提交、决定、递送和回票各阶段可见；N8 要求冲突与结果不明分开（`uta-design.md:119-120`）。
- Q1 要求受理、部分成交、成交三张回票依次可见并保留原生字段；Q5 要求专有状态不被压成被拒；Q10 要求版本冲突不改变指令状态（`uta-design.md:130-139`）。

## 决定
- 帐票按种类记录指令、决定、递送进度、回票、对账响应、外部变动、人工凭证和缺口；所有帐票不可变、只追加，引用只能指向已存在的帐票（§2.2，`uta-design.md:172-185`）。
- 指令状态不作为可写字段，而由指令手里已有的帐票计算；批准、递送、结果不明、回票和人工结论按 §2.3 的规则解释（`uta-design.md:187-200`）。
- 回票保留 broker 原生 id、状态原值、成交字段和原始负载摘要，并依 broker 状态偏序单调折叠；迟到旧状态不能覆盖新状态，重复回票按事件 id 或指纹去重（R4/R5、§2.3，`uta-design.md:201-207`）。

## 被否决的替代
- 账本：把本地汇总当作交易事实会违背 broker 是事实权威的约束。
- 每账户存折：以账户余额式快照代替不可变帐票会丢失阶段、来源和关联依据。

## 后果与验证
- 客户端可以沿帐票重建指令视图，崩溃恢复只需重放追加记录；代价是状态读取需要按规则折叠，索引只能作为可重建加速结构。
- Q1 应观察三张回票按顺序到达且原生 id 与成交字段完整；Q5 应观察专有状态保留原值、未列举状态标不明并告警；Q10 应观察第二个相同期望版本只产生冲突记录且指令状态不变（`uta-design.md:130-139`）。
- Q17 应证明追加帐票中途崩溃后重启只保留完整记录，不出现半条记录（`uta-design.md:146-147`）。
